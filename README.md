# 时光集：X / Instagram 历史合集

当前版本 **1.28.2**。输入博主用户名，查找公开历史存档，整理正文、图片和视频，并按发帖时间浏览或下载离线合集。

## 下载与启动

**Windows 用户：[下载最新便携版](https://github.com/hyunfan/shiguangji-release/releases/latest)。** 面向 Windows 10 / 11 x64；完整解压即可启动，无需另装 Python、Node.js 或 Codex。可选视频合并组件按需安装。

1. 在发布页的 **Assets** 中下载文件名以 `-windows-x64-portable.zip` 结尾的压缩包。
2. **完整解压**到一个有写入权限的文件夹，保留包内所有文件和 `python` 子目录。
3. 双击 **启动工具.cmd**，等待浏览器打开；之后可运行 **创建桌面快捷方式.cmd**，从桌面进入。

GitHub 自动提供的 **Source code** 压缩包不含 Python 运行环境，需要按下方源码方式启动。这个 Windows 便携包不能直接在 Android、macOS 或其他系统运行。启动无响应或窗口闪退时查看包内 [开始使用.txt](开始使用.txt)；提交问题前先移除日志和截图中的个人资料。

没有留下可访问存档的内容仍可能无法恢复。找到帖子链接、封面或媒体地址，不等于已恢复原文件；只有成功保存并校验的文件才计入下载数。

## 存储方式

历史网页及备份中的网页对象支持无损压缩，图片、视频保持原样。新归档自动压缩；已有资料可在“空间管理”点击“无损压缩历史网页”。每份文件均在压缩写入、解压校验及最终位置读回通过后替换；中断后再次点击可继续。下载 ZIP 和恢复到新目录时会输出普通网页文本，旧备份索引保持兼容。具体节省量以实际结果为准。

## 从源码启动

本仓库保存程序源码、测试和维护文档，不包含博主资料、历史媒体、数据库、日志、代理凭据或个人运行记录。主要使用与验证环境为 Windows x64。

准备 Python 3.10 或更新版本。复制当前仓库页面 **Code → HTTPS** 中的克隆地址，替换下方占位地址后执行；私有仓库需要先取得访问权限：

```powershell
git clone <仓库克隆地址> shiguangji
cd shiguangji
python -X utf8 app.py --open
```

也可完整下载并解压源码后双击“启动工具.cmd”。基础功能使用 Python 标准库，无需安装 pip 包；只有完整测试需要 Node.js。源码仓库不包含内置 Python 或 FFmpeg，便携包的构建方法见 [维护说明](ARCHITECTURE.md)。

## 媒体统计

合集顶部区分原始记录和媒体分类：**已存文件记录 / 未存链接记录**保留原来的条目数量；下面单列**已保存视频、未保存视频、图片、视频封面**。同一帖子内可明确识别为同一视频的多个清晰度和播放列表只计一组，有一个视频版本保存成功即计为已保存视频。封面不算视频恢复成功。

展开“媒体统计说明”可查看已有视频但仍缺版本的数量、摘要相同的记录，以及无法确认身份的记录。身份不明或冲突时分别计数，不根据相似文件名强行合并。这是当前记录的整理统计，并非全量恢复率。旧合集直接在主页面查看即可计算新统计；已生成的离线页面与 ZIP 需要重新导出后才会包含新版统计。

## 日常使用

1. 双击桌面“时光集”快捷方式，等待浏览器打开。没有快捷方式时，双击安装目录的“启动工具.cmd”。Windows x64 便携版内置 Python，完整解压即可使用；源码版需要 Python 3.10 或更新版本，无需安装 pip 包。可运行“创建桌面快捷方式.cmd”创建入口。
2. 添加博主时选择 **X / Twitter** 或 **Instagram**，填写用户名或主页链接，点击 **开始查找与下载**。
3. 添加多个账号时使用批量队列，每行一个。当前账号完成保存与备份后自动处理下一个；暂停队列后需主动继续。
4. 在线浏览默认载入 40 条帖子，点击“加载更多”继续。搜索、月份、图片/视频等筛选针对整个合集。
5. 任务结束后选择 **打开离线版**；需要下载时点 **生成下载包**，生成后再下载。已有 ZIP 可直接下载；应完整解压后打开 `index.html`。

关闭网页不会停止后台任务。需停止采集时点 **暂停并保存**；需退出后台时运行“停止后台.cmd”。保持按需启动，不自动随 Windows 登录运行。网页未连接时使用桌面快捷方式启动，页面会重连。

任务期间会尝试阻止 Windows 自动休眠，屏幕仍可熄灭。手动休眠、合盖策略、断电或强制关机仍可能中断任务；重新启动后按保存进度继续。

## 网盘或外部目录备份

在“运行保护与备份”中勾选 **同时备份到同步或挂载目录**，填写专用空文件夹的绝对路径，点击 **保存网盘备份设置**。启用时会同时打开本地任务结束备份。

工具使用文件系统复制，不直接登录网盘，也不绑定某个客户端、盘符、卷名或文件夹名称。目标可以是网盘客户端的本地同步文件夹、挂载盘、具有读写权限的网络共享，或外接盘。CloudDrive 是挂载工具的一个例子，并非必需组件。只提供网页上传、没有本地可访问目录的服务不能直接使用此功能。

先在所用客户端完成登录和连接，并确认目标的上级目录已存在、可以读写。可选择其中一个专用空文件夹，或填写其下尚未建立的最后一级文件夹；不要选择混有其他文件的目录。Windows 本地路径和 `\\服务器\共享\专用备份目录` 均可，按自己的设备填写，**不要求使用 E 盘或任何固定名称**。选择普通本地文件夹只会复制到该文件夹；是否上传、按需下载或离线可用由所用客户端决定。

工具每分钟检查已有及新生成的 `collections-backups` 索引，独立复制到目标目录，完成内容摘要读回校验后记录交付结果。没有本地备份的旧合集不会自动纳入，可运行下文的全库本地备份命令。暂停的任务也会在保存后生成备份；正在采集的内容要等本地备份完成。只追加，不联动删除云端文件；关闭功能后已保存副本保留。

首次连接会建立资料库和目标目录标识，并在本地保存核对记录。后续标识缺失或不一致时停止写入，避免盘符重用或目录切换后写错位置；不要删除 `.shiguangji-backup.json`。旧版目录可沿用原标识，已有交付记录不会强制重传。需要改用新的空目标时，请选择另一个专用目录并保存设置。

网盘断开或复制失败不阻塞归档任务：5 分钟后重试，连续失败逐渐延长到最多 1 小时。连续 3 分钟无读写进展会结束本工具的复制子进程，保存下次重试机会，不结束同步客户端。正常退出时光集时停止复制，下次双击启动后继续检查本地备份；客户端自己的上传队列由它管理。

**“已复制并校验”表示目标目录读回通过，不代表网盘服务端已上传完成。** 同步或挂载客户端可能先把写入放进本地缓存。请在所用客户端检查上传状态，再通过网盘官网或另一设备核实；此前的交付记录不表示实时检查云端文件是否仍存在。保留本地副本，勿仅凭目标目录可见就删除本地资料。

1.24.1 起，新网盘副本放在“恢复包”文件夹，每个博主一个完整 ZIP，避免大量小文件上传。先下载并完整解压所需 ZIP，再按下方方法将 `--restore` 指向解压目录中的账号 JSON；其中的 `objects` 目录和数据库 ZIP 都需要保留。打包和复制期间可能额外占用该博主备份大小约两倍的本地空间，空间不足会稍后重试。成功交付后删除本工具可再生成的传输缓存，网盘客户端自身缓存由它管理。

旧版直接写在网盘根目录的账号 JSON、`objects` 和数据库 ZIP 仍有效，不强制重新上传。恢复备份保留原始资料，离线浏览网页和合集 ZIP 可恢复后重新生成；网盘旧快照不自动清理，因此需要按实际使用量管理网盘空间。

## 减少本地空间占用与网盘试读

展开页面的 **本地空间与网盘试读**。1.26.0 默认按需生成下载 ZIP，任务结束时仍保存完整离线页面和按设置执行恢复备份。取消该选项可以恢复每次任务结束后自动打包；已有 ZIP 不会因升级而删除。

- **预览可释放 ZIP**：列出超过所选天数且可以从现有文件重新生成的下载包；也可预览全部。核对清单并确认后才删除 ZIP，原始媒体、数据库、离线页面和恢复备份保留。预览有效期为 30 分钟；清理时重新核对文件内容，变化或缺少原件的项目会跳过。所选天数只是预览条件，不会定时自动删除。
- **数据库快照保留份数**：下一次该合集完成本地备份时生效，默认三份。只整理旧数据库快照，共用媒体备份对象保留，不是删除整个本地恢复备份。
- **试读当前合集**：选择一个已生成新版网盘恢复包的合集，各选一张图片和一个视频进行校验试读（若存在，单个不超过 200 MiB）。从现有恢复包读出完整文件，核对 SHA-256 后才提供播放；首次打开需等待完整文件缓存，之后可在缓存中拖动播放。单次网盘读取最多 120 秒，失败会停止此次读取并显示结果。
- **试读缓存**：默认上限 5 GiB，可改为 1、10 或 20 GiB，按最近使用时间释放未播放的缓存；正在使用的文件保留。网盘客户端自身缓存和上传临时文件另计。缓存可以单独清理。

这版提供网盘读取试验，尚未把日常浏览改为纯云内容库，也不会释放媒体原件。数据库、索引和离线页面仍在本地。目标目录读回可能命中客户端缓存，不证明网盘服务端上传完成；实际首播速度还取决于网络与文件大小。不要手动把 `collections` 整个目录搬到网盘，或根据试读成功删除原件。

## 运行保护与备份

双击桌面快捷方式会同时启动后台与守护，网页“运行保护与备份”显示守护状态。守护仅在确认后台进程意外退出后恢复网页服务，一小时最多三次，不因慢请求或保存耗时强行重启。正常“停止时光集”后守护也退出，不增加 Windows 登录自启。系统休眠、关机时守护无法运行。

“后台崩溃恢复后，自动继续原先运行的队列”默认关闭。开启后也仅恢复退出时仍运行的同一次排队任务；主动暂停、正常退出、单独启动的任务不会自动继续。冷却期内的失败链接不会在换批后立即请求，结束标识会说明还有待查项目；冷却结束后可继续该账号。404 并不证明媒体永久不存在。

每个账号任务结束后（包括暂停）默认备份至安装目录的 `collections-backups`。备份包含该账号的媒体、原始页面、SQLite 数据库、清单，以及当时的全库账号记录与队列记录；**一次账号备份不包含其他账号的媒体**。文件按 SHA-256 内容摘要共用存储，相同内容只复制一次；每次复查摘要，数据库快照保留最新三份。备份失败会暂停后续队列，页面保留错误原因。大合集首次备份需要额外时间和接近原始媒体大小的空间。

备份期间保持防休眠；下载、导出和备份会检查剩余空间，预留 256 MB 用于保存进度。日志自动轮换。空间不足时先释放空间，再继续队列。预留空间不能防止其他程序同时占满磁盘，也不能替代硬盘故障防护。

便携版可在安装目录打开 PowerShell，将全库备份到自己选择的目录。下例在当前目录旁建立本地备份和恢复检查目录；需要外接盘或同步目录时，改为自己的绝对路径，盘符和名称均可自定：

```powershell
$BackupDir = Join-Path (Get-Location).Path '..\archive-backup'
$RestoreDir = Join-Path (Get-Location).Path '..\archive-restore-check'
.\python\python.exe -X utf8 .\shiguangji\storage\backup_library.py --output $BackupDir
```

恢复前先用“停止时光集”退出后台。下面恢复一个账号到**尚不存在的新目录**，先验证备份再写入，不覆盖原资料：

```powershell
.\python\python.exe -X utf8 .\shiguangji\storage\backup_library.py --restore (Join-Path $BackupDir 'alice.json') --restore-to $RestoreDir
```

`alice.json` 是虚构账号示例，替换为实际的备份索引文件名；网盘恢复包要先完整解压，再选其中的索引。恢复后可把新目录作为独立资料库启动检查：`.\python\python.exe -X utf8 .\app.py --data-dir $RestoreDir --port 8767 --open`。该端口须空闲；离线文件和 ZIP 可在合集页重新生成。源码版将上述 `.\python\python.exe` 换为系统 Python。保留整个备份目录，包括 `objects` 文件夹；不要只复制账号 JSON。相同硬盘上的备份不能防止磁盘损坏。

## 查找以前的博主、继续旧任务

点击左侧 **查找博主与历史任务**，输入用户名、已核实的旧用户名或数字 ID。可同时按 X / Instagram 和任务状态筛选；每页 20 条，使用上一页、下一页翻查。点击 **打开合集** 可直接定位到已保存内容。

筛选 **暂停、中断或失败**，再点击对应记录的 **继续此任务** 或 **重试此任务**。保存过的正文、媒体与检查点会保留，沿用该次记录的采集设置；代理地址使用当前高级设置。旧版记录缺失的设置使用当前值。若只是打包失败，按钮为 **重新生成 ZIP**，不会重新采集。当前有任务运行时，先等待结束或暂停并保存。

每次继续会新增一条运行记录，原来的暂停或失败记录仍保留。继续完整归档时，如果该博主也在暂停的队列中，会更新它对应的队列项目，其他项目仍保持暂停；仅查帖子、补全媒体或重新打包不会完成队列中的完整归档项目。需要批量执行时另点 **继续队列**。任务开始前失败、尚未生成合集的博主，也可通过历史记录重试。

历史记录保存在 `collections/.task-history.sqlite`，清除队列结果不会清除历史。旧版本首次使用时，只能补录现存合集、最近任务和仍保留的队列结果，**已被旧版本覆盖的历史无法补回**。此后从网页启动的任务会持续保存；命令行直接运行采集器不写入这份历史。删除博主时会一并删除该博主的历史记录。

## 看懂结果

| 显示 | 含义 | 建议操作 |
|---|---|---|
| 正在查找 / 正在保存与打包 | 后台仍在运行 | 等待，或暂停并保存 |
| 已暂停，等待继续 | 主动暂停或达到运行限制 | 需要时继续任务 |
| 本轮查找完成 | 当前计划范围检查完 | 浏览或下载；不代表账号全量资料 |
| 本轮已结束 | 如连续多批没有进展 | 查看结束原因，无需反复立即点击补全 |
| 任务失败 / 意外中断 | 有错误或后台中断 | 查看错误，修复后继续 |
| 部分恢复 | 已保存部分内容，仍有缺失 | 展开媒体的来源记录了解原因 |

运行时离线版显示上次完整保存的结果，在线页面显示最新检查点。自动换批只保存数据库和在线清单，避免每批反复生成整套离线文件；暂停或任务结束时再生成完整离线版，ZIP 默认按需生成。强制关闭后仍可按数据库中的进度继续。旧数据初次打开需要建立读取缓存，后续列表刷新只读取摘要。

任务卡片直接显示当前阶段已用时间和最近一条处理记录。X 快照进度为整个合集累计成功解析数，换批不会从零重新计算；读取失败不计为成功。展开“处理详情与记录”可查看本次任务各阶段累计耗时。网络重试、保存和 ZIP 仍需要时间，阶段进度不代表整个归档完成比例。

## 账号与来源

- X 会自动查找历史用户名线索；只有数字作者身份等证据通过核对的名字才参与关联。昵称、头像相似或互相关注都不能单独证明是同一个账号。可在“更多 → 历史用户名”补充线索。
- Instagram 与 X 同名账号分别保存。Instagram 支持主页历史快照、帖子、Reels、旧 IGTV 和轮播媒体，也可补充已知帖子链接；当前没有自动旧名关联功能。
- Wayback、Common Crawl 和公开帖子资料用于发现和恢复文件。当前 CDN 文件会标明来源，不冒充历史快照。可在高级设置关闭相应公开来源。
- Common Crawl 先查有时间依据及近期范围，再检查更早范围；待查顺序和失败结果会保留，不会因为进入下一批就从头开始。
- 图片/视频会做格式、结构和完整性检查；校验通过仍不保证浏览器支持该视频编码，可下载后用本地播放器查看。
- HLS 视频分片支持同一明确 X 视频的完整、无加密 TS / fMP4 点播列表，需安装可选视频组件；加密、缺片、字节范围及时间断点等列表会保留入口。登录、访问限制、网络失败以及未被存档的文件，可能无法恢复。

## 数据和删除

页面的“保存位置”显示当前后台的数据目录。安装目录的 `collections/` 包含各博主的数据库、原始快照、媒体和离线文件。X 使用用户名目录；Instagram 使用 `instagram--用户名`。

`manifest.json` 为完整清单，`posts.jsonl` / `posts.csv` 为正文数据，`missing-media.json` / `errors.json` 为未恢复内容与错误。`generation.json` 为导出文件校验记录；`summary.json` 为列表读取缓存。

删除博主会删除其本地合集；操作前先暂停任务、移除相关待处理队列项，并仔细确认账号。希望保留备份时先下载 ZIP。

## 启动或连接问题

- 窗口一闪而过或页面连不上：重新运行“启动工具.cmd”，查看安装目录 `runtime/` 中的启动日志。
- 使用桌面快捷方式打开正确端口；不要仅凭旧书签判断后台是否启动。
- 页面展示的是当前后台版本和保存位置，升级后可刷新核对 **1.28.2**。
- 网络查询失败会保留已保存内容。设置本机 HTTP 代理时填实际地址，例如 `http://127.0.0.1:7890`，端口以自己的代理设置为准。

## 分享与迁移

向使用 Windows 10 / 11 x64 的人发送 `shiguangji-1.28.2-windows-x64-portable.zip`。对方完整解压后双击“启动工具.cmd”；无需安装 Python、Node.js 或 Codex。包内不含你的合集、任务状态和日志。使用方法见 [开始使用.txt](开始使用.txt)。

迁移自己的数据时先停止后台，再复制整个程序文件夹到新电脑；从新位置启动并核对页面的保存位置。同一台电脑不要同时运行新旧两份。已有其他目录的快捷方式或协议时，创建工具会报告冲突，可继续通过目录内的启动脚本使用；创建入口后应保持目录固定。

内置 Python 来自官方嵌入式发行包，许可保留在 `python/LICENSE.txt`，原始来源和校验值记录在 `portable.json`。发布包中的 `release.json` 含所有程序文件的校验值。便携版针对 Windows x64，不是其他操作系统或 ARM64 的原生发行版。

版本历史见 [CHANGELOG.md](CHANGELOG.md)，模块边界、测试及发布回退见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1.25 恢复改进与使用

- 保持“自动继续”和“多源恢复”开启。来源暂时不可用时，任务保存进度、让出队列，显示下次重试时间；每项最多延后重试 3 轮，且不超过首次延后后的 48 小时。暂停队列会停止自动推进，重新启动工具后仍需手动继续队列。等待期间不阻止电脑休眠，电脑重新唤醒且后台仍运行时会检查到期任务。
- 每批最多对 12 条已有但缺正文的 X 帖子补取公开资料，使用约 90 秒的阶段预算并共享整批请求/时间上限。必须匹配帖子 ID 和作者；已知作者数字 ID 时不得仅凭同名采用。正文保留当前公开来源、核对身份及时间，历史正文优先。访问受限的帖子不做此补取。
- 合集诊断区区分页面未读、页面已读但待解析或换快照、空壳页、访问受限、尚无对应快照。它们是已观察到的状态，不能证明全网没有资料。
- 视频组件：完整解压后双击“安装视频组件.cmd”。组件来自 FFmpeg 官网链接的 Windows 提供方 Gyan，下载后校验 SHA-256，只写入工具目录，不更改系统 PATH。标准便携包不含这些可选二进制文件，不安装也能使用原有归档功能。网络问题导致下载失败时窗口会保留报错。
- HLS 由工具限量下载同一视频的分片，FFmpeg 只读取重写后的本地列表；合并后检查轨道、时长、容器并完整解码，通过后才发布 MP4。完整分片及摘要保存在各合集 `.hls-cache` 内，后续可复用，损坏分片会重取；该临时缓存不加入浏览合集 ZIP。播放器是否支持编码仍取决于浏览器。
- 本轮累计请求、帖子、正文和文件增量分开记录；媒体记录可能包含同一视频的多个版本，应同时参考去重视频统计。真实来源返回 404、缺少存档等情况仍可能无法恢复。

视频组件来源：[FFmpeg 下载页](https://ffmpeg.org/download.html)、[Gyan Windows builds](https://www.gyan.dev/ffmpeg/builds/)。
